# Claude Cream Image Generation

Claude Cream 的图像生成规范，覆盖网站插画、个人社交头像和桌面或移动端壁纸。三类资产共享同一套暖象牙、深炭黑和琥珀金视觉语言，但各自使用独立的构图与验收规则。

## 统一视觉基线

- 背景以暖象牙、奶油色、旧纸色或暖炭灰为主，避免纯白、纯黑和冷灰。
- 深炭黑用于主体结构，琥珀金只强调一个关键位置。
- 青绿色可以作为微小状态点，也可以完全不用。
- 材质偏向旧纸、天然亚麻、哑光金属、做旧黄铜和轻微灰泥表面。
- 光线柔和、方向明确，阴影真实但不过重。
- 画面保持克制和低干扰，不使用冷蓝紫霓虹、玻璃拟态和高饱和渐变。
- 不生成标题、Logo、水印、网址、签名、可读 UI 或随机字符。

具体色值和网站插画的基础风格记录在 [`style.json`](style.json)。

| 类型 | 提示词 | 主要用途 | 验收重点 |

## 网站插画

### 风格

暖色编辑工坊中的微缩叙事装置。画面把软件、工作流或抽象概念转译成可触摸的机械物件、纸张档案与桌面模型。

主体通常位于画面中右区域，左侧保留可叠加标题的负空间。材质以深炭黑金属、旧纸、亚麻和黄铜为主，琥珀金用于路径、节点或关键结构。画面采用轻微俯视或平视三分之四视角，保持柔和自然侧光和编辑摄影质感。

### 参考资产

以下封面来自 KAKARROT Website 项目，用于校准网站插画风格，不随本仓分发：

```text
kakarrot-website / cover.webp
wukong / cover.webp
claude-cream / cover.webp
```

### 推荐规格

- 网站横版封面：`1600 × 900`，比例 `16:9`
- 社交分享图：`1200 × 630`
- 安全区：左侧约 38% 不放关键主体，底部约 20% 避免高对比细节
- 输出格式：归档使用 PNG，网站交付使用 WebP

### 使用

1. 复制 [`illustration-prompt-template.md`](illustration-prompt-template.md) 的完整内容。
2. 填写主题、核心机制、画幅比例、用途和主体偏好。
3. 将参考封面作为风格参考图，不要作为编辑目标。
4. 生成后检查核心隐喻、留白、材质、文字安全区和随机字符。
5. 保留 PNG 源文件，将压缩后的 WebP 用于网站。

## 个人社交头像

### 风格

自然、克制的编辑肖像。人物身份特征优先于风格化处理，背景保持简单，光线柔和，服装和细节使用 Claude Cream 色板。

### 推荐规格

- 画幅比例：`1:1`
- 源文件：建议至少 `2048 × 2048`
- 裁切检查：同时检查方形原图和圆形缩略图
- 输出格式：保留无损 PNG，再按平台要求转换

### 使用

1. 复制 [`avatar-prompt-template.md`](avatar-prompt-template.md) 的完整内容。
2. 上传 1 至 3 张清晰参考照片，至少包含一张自然光正脸。
3. 填写人物气质、身份、希望保留的特征和服装偏好。
4. 检查相似度、真实年龄、自然肤色和面部比例。
5. 缩小并套用圆形蒙版，确认头发、眼镜、下巴和识别特征没有被裁切。

## 壁纸

### 风格

壁纸使用更低的细节密度和对比度。视觉中心不能抢夺窗口内容，图标、菜单栏、Dock、任务栏和移动端时间区域需要稳定、低干扰的背景。

### 推荐规格

- 桌面壁纸：按设备原生分辨率生成，常用比例为 `16:10`、`16:9` 和 `21:9`
- 移动端壁纸：按设备原生分辨率生成，顶部预留时间和状态信息安全区
- 输出格式：保留无损 PNG，再按设备要求转换为 JPEG、HEIC 或 WebP
- Dark 模式避免纯黑，Light 模式避免大面积纯白

### 使用

1. 复制 [`wallpaper-prompt-template.md`](wallpaper-prompt-template.md) 的完整内容。
2. 填写设备类型、原生分辨率、画幅比例、系统模式和图标区域。
3. 桌面壁纸检查菜单栏、Dock、任务栏和图标安全区。
4. 移动端壁纸检查时间、通知、灵动岛或刘海区域。
5. 在实际设备上预览，确认窗口打开后壁纸会自然退到背景。

## 验证

- `style.json` 必须能被标准 JSON 解析器读取。
- 三类提示词都要保持 Claude Cream 色板和统一负面约束。
- 网站插画检查单一隐喻、留白和文字安全区。
- 头像检查身份特征、方形原图和圆形缩略图。
- 壁纸检查原生比例、系统组件安全区和实际设备显示效果。
- 新文件加入项目后检查 README 链接，并运行 `git diff --check`。
